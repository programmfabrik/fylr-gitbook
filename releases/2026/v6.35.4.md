## fylr core

### New

#### Docker installations: maintain updates fylr by the digests of a release record

Every release has a release record for each of its tags, a small file in [fylr-gitbook](https://github.com/programmfabrik/fylr-gitbook/tree/main/_assets/releases) that names the digest of each image of the tag. `maintain update`, `start`, `update-fylr` and `pull` of a Linux docker compose installation read the record of the tag in `docker-compose.yml`, pull the images of fylr with exactly these digests and give them the tag on the host, where they pulled by the tag before. The release records are in another place than the images, so a tag changed in the registry brings no other image onto the host. fylr is not updated and keeps running when the record cannot be fetched, the tag has none or the registry does not have the image; the cron mail says which. Releases from 6.35.3 on have records, and a tag without one is pulled by its tag when it is named in `UNVERIFIED_TAGS`. The script does not update itself: a release can need a newer one, and an older script then stops updating and says at every call that it is deprecated. The text of a release on GitHub and its page in the documentation start with the docker images and their digests and the SHA-256 of each download. → [How maintain updates fylr](https://docs.fylr.io/for-system-administrators/installation/linux-docker-compose#how-maintain-updates-fylr) [13096a4e6]

### Improved

#### File uploads: `eas/rput` from a server whose `HEAD` names no size

`POST /api/v1/eas/rput` and `/api/v1/eas/rput/bulk` send a `GET` when the URL answers the `HEAD` with `200` but with a `Content-Length` of `0` or with none, and take filename, size and type from the `GET`. A `Content-Length` of `0` in the `HEAD` was refused with `400 EasRputErrorContentLength`, a missing one too with `leave`, and without `leave` the file was registered without its size, although the `GET` of such a server delivers the file with its size. Uploads from such a server no longer need `skip_head_request`. A URL whose `GET` names no size either is handled as before. → [eas/rput](https://docs.fylr.io/for-developers/api/endpoints/eas/rput) [b69ae7778]

### Fixed

#### A queue of items that need no execserver no longer runs fylr out of memory

The file worker raised the number of queue items it works on at once while the execservers reported free slots. Items like `sync_check`, which an import queues for every file, never use an execserver and run in fylr itself. A long queue of them drove that number to its ceiling and fylr out of memory, again after every restart. The number now rises above its base only while jobs of this fylr run at the execservers. It also comes down when more than half of the database connections are in use or a request waits for one, so a resync of all originals no longer makes the requests wait for the database. A `fylr.execserver.maxInFlight` set as a workaround can be removed after the update. [2710526cd] [a4e886904]

#### File uploads: `eas/rput` through a proxy

`POST /api/v1/eas/rput`, `/api/v1/eas/rput/bulk` and the copy of the remote file go through the proxy that `HTTPS_PROXY`, `HTTP_PROXY` and `NO_PROXY` name for the url, as fylr's other outgoing requests do. From 6.33.0 they connected to the file's host on the port of the proxy instead, so behind a proxy every such upload failed with `proxyconnect tcp: dial tcp <address of the host>:<port of the proxy>`, mostly `i/o timeout`. fylr itself still resolves the host, and that of every redirect, to check it against `fylr.eas.rput.blockedHosts`. [da7549d7f]

## Web frontend

### Improved

* The download dialog no longer preselects the first version of each class. The first time nothing is selected, then the dialog starts with the versions and the base configuration's custom renditions picked in the last download, per user and browser; custom renditions set up in the dialog are not remembered. *Include Files of Linked Records* leaves out the files that linked records add to a download; it shows when the selected records have files of their own, is ticked by default and is remembered like the versions. The file counter shows the total size of the picked versions and how much of it comes from linked records. [620a4049b] [d94b0b4ac]

### Fixed

* With the result card pinned, the sidebar editor scrolls over its whole height again; from 6.35.0 to 6.35.3 it did not. [a845ec41d]
* In the export field selection, ticking a field ticks its sub-fields also while it is expanded, and a field shows whether all or some of its sub-fields are ticked. A field of a custom data type has a row of its own for its complete value, under the key the field had, so saved exports and templates keep working. [191b2250d]
