## Frontend

### Fixed

* **Switching a record's mask by changing its tag or pool works again**: A tag
  or pool change that moves the record to another mask is saved on its own,
  before the editor reloads with the new mask. Since 6.33.0 that save carried
  the mask the record switches *to*; fylr checks the mask right against the
  stored record, with its old tags and pool, so a mask the user only holds
  through the new tag was refused with *needs right "Allowed Masks: …"* and the
  tag stayed as it was. Instances whose masks are granted per tag could not
  reclassify a record at all. The save carries the record's current mask again,
  as it did up to 6.32, and the mask switch follows. (e2610a51d) (7f6dd0bd1)

* **"Modify tags" no longer trips a workflow that requires a tag of the group**:
  The dialog sent one request removing the old tags and a second one adding the
  new ones. With a choice group the record had no tag of that group in between,
  so a transition that rejects a record without one fired on the first request
  and the new tag was never set — while the same change made in the editor,
  which sends the final list at once, went through. The tag is added first now;
  for a choice group the server drops the other tags of the group on add, so
  the remove that follows changes nothing. (c979d5189)

* **No exception when the "Edit" flyout of the selection menu opens**: Opening
  the flyout ran the tool setup with the flyout's own entries, which have no
  "Modify tags" tool, and threw on enabling it, leaving the rest of the setup
  undone. (531a1c218)
