## Server

### Important

Each item is a heads-up; the full entry is linked.

* **The upgrade migrates the database and runs a full re-index.** Both are blocking: only `/inspect/` answers until the re-index has switched in. Allow time on a large instance. → [Recursive standards and indexing](#recursive-standards-and-indexing), [re-index](../../for-system-administrators/inspect/system.md#re-index).

* **Everyone is logged out once.** The cutover to fylr's own OAuth2 server deletes every stored token; browsers log in again, scripts fetch a fresh token. The `openid` scope is **rejected** — remove it from clients. → [fylr's own OAuth2 authorization server](#fylr-has-its-own-oauth2-authorization-server), [OAuth2](../../for-developers/api/oauth2.md).

* **A proxy in front of fylr has to be declared.** Forwarded client addresses (`x-real-ip`, `x-forwarded-for`) are honoured only with `fylr.trustProxyHeaders: true`, **off by default**. A proxy on another host, a container network or a Kubernetes ingress needs it, or IP-filtered groups, the login lockout and the audit log see the proxy's address. → [Client address behind a proxy](#client-address-behind-a-proxy), [proxy and fylr](../../for-system-administrators/installation/linux-docker-compose/proxy-and-fylr.md#trusting-a-proxy-for-the-client-address).

* **Execserver and fylr are upgraded together.** The polling transport is removed; an execserver of another version exchanges no jobs. `parallel`, `parallelHigh`, `tokenResponseSendServerIP`, the `waitgroups` block with its per-service `waitgroup` keys, and per-service `commands` are gone, reported as deprecated at startup and ignored; a `/job/<service>` path on an execserver address is refused; `callbackBackendInternalURL` / `callbackApiInternalURL` no longer supply the host. → [Execserver scheduling and execution limits](#execserver-scheduling-and-execution-limits), [Updating the execserver to 6.35](../../for-system-administrators/installation/updating-the-execserver-to-6.35.md).

* **`fylr restore` needs a backup taken with 6.35.0 or newer**, and `--file-api-access-token` is removed. → [A backup carries its own file authorization](#a-backup-carries-its-own-file-authorization), [restore](../../for-system-administrators/migration/restore.md).

* **The easydb plugins no longer ship with fylr.** Enabled ones with a marketplace successor are converted on upgrade; the instance must reach the plugin sources, and `easydb-editor-field-visibility` is renamed. → [The easydb plugins migrate to the marketplace](#the-easydb-plugins-migrate-to-the-marketplace), [Disk to URL plugin migration](../../plugins/disk-to-url-migration.md).

* **A rejected access token is `401` `InvalidToken` on every endpoint** — no longer `400` on `/user/session` and `/oauth2/refresh`. → [A rejected access token is 401 InvalidToken everywhere](#a-rejected-access-token-is-401-invalidtoken-everywhere).

* **A saved file-handling configuration is migrated**: EPS and AI rasters render from the original, and the stored wiring is split the way the shipped default declares it. → [EPS and AI render with ghostscript](#eps-and-ai-render-with-ghostscript).

* **`Generic XYZ Profile` and `Generic Lab Profile` are gone**; a custom version preset naming either no longer saves. → [Colour profiles offered for a download](#colour-profiles-offered-for-a-download).

* **A pool's standard masks decide what is indexed**, not only what a search returns; changing them re-indexes the pool's records after confirmation. → [Masks below the line in a pool are no longer indexed](#masks-below-the-line-in-a-pool-are-no-longer-indexed).

* **Stricter validation on save**: a recipe value outside the recipe's range refuses the file-production settings; a field type change is checked against the conversion matrix with or without data; a saved data language's code is read-only. → [A recipe setting the production cannot use is refused](#a-recipe-setting-the-production-cannot-use-is-refused), [Field type changes are validated the same way](#field-type-changes-are-validated-the-same-way-with-and-without-data), [Editing a data language code](#editing-a-data-language-code-can-no-longer-orphan-values).

* **Removed**: the `fylr pdf2pages` subcommand (→ [video timeline frames](#a-video-produces-preview-frames-for-the-player-timeline)); the `X-Easydb-Base-Schema-Version` / `X-Easydb-User-Schema-Version` headers; the `plugin.webfrontend.readme` and `version` manifest keys (→ [Plugin marketplace](#plugin-marketplace)); `Access-Control-Allow-Private-Network`.

* **New defaults that may need attention**: `X-Frame-Options: SAMEORIGIN` on every response — a portal embedding fylr cross-origin lists its origin in `fylr.services.webapp.frameAncestors` (→ [Security policy headers](#security-policy-headers-on-every-response)); credentialed CORS only for configured origins (→ [CORS](#cors-credentialed-requests-limited-to-configured-origins)).

* **Recommended after the upgrade, not forced**: a full re-index is part of the upgrade, so [dates in the full text](#dates-are-searchable-in-the-full-text) and [pool standard masks](#masks-below-the-line-in-a-pool-are-no-longer-indexed) apply to existing records. A **resync** of the affected files is needed for [video timeline frames](#a-video-produces-preview-frames-for-the-player-timeline), a **resync with metadata** for [360° media](#360-media-are-recognized), and a **re-produce** for [3D assets](#3d-assets), [EPS and AI](#eps-and-ai-render-with-ghostscript) and [percentage watermarks](#a-watermark-sized-in-percent-keeps-that-percentage) uploaded before this version, and a re-run of the OCR recipe on [multi-page TIFFs](#ocr-reads-every-page-of-a-multi-page-tiff). See [Files and version production](../../for-system-administrators/inspect/files.md).

### New

#### Base fields only group edits

`POST /api/v1/db/{objecttype}` accepts `base_fields_only=1` to change tags or pools of records editable through different masks: send the `_id` array without `_mask`; fields, parents, owners and record ACLs stay unchanged, write permission, tag-edit policy and pool permissions still apply. Repeated tag and pool edits share unchanged value sets between record versions. → [/api/v1/db](../../for-developers/api/endpoints/api-db.md#base-fields-only-group-edits). [4a26c76c3]

#### A video produces preview frames for the player timeline

Videos get a `pages` version — a `pages.zip` like documents have — with up to 100 frames at least half a second apart, at 200 and 320 px, plus tiled contact sheets. The frame list arrives in the version's `info.json` via `GET /api/v1/eas`; a frame is served from the zip by `/api/v1/eas/download/<id>/<hash>/<version>/<path-in-zip>`. `fylr convert --format pages.zip` produces it for documents and videos; **`fylr pdf2pages` is removed** — a custom recipe calling it has to change. Existing videos get the version on resync. → [The pages version](../../for-developers/file-worker.md#the-pages-version-many-images-in-one-version). [4eebf3c25, 68a54b280]

#### A multi-page TIFF gets a pages version

A TIFF with more than one page gets the `pages` version office documents and videos have, so a scan reads page by page; a single-page TIFF is unchanged. Existing multi-page TIFFs pick it up on their next resync. → [The pages version](../../for-developers/file-worker.md#the-pages-version-many-images-in-one-version). [17fc71f7a]

#### The contents of a ZIP can be browsed in inspect

`/inspect/files/<id>/` shows an archive — a `.zip` or a produced `pages.zip` — as a tree beside a preview: images, video and audio play in place, JSON gets the tree and raw view, markdown is rendered, common text formats are highlighted, anything else offers a download. → [Files](../../for-system-administrators/inspect/files.md#browsing-a-zip). [17fc71f7a]

#### Plugin marketplace

An in-app catalog of installable plugins: `GET /plugin/marketplace` and `GET /plugin/marketplace/{name}/readme` (`system.root` or `system.plugin`). The catalog is pulled from Programmfabrik's published sheet and cached; until a first copy loads, the endpoints answer `503 PluginMarketplaceUnavailable`. Paid and private plugins are delivered **sealed** and decrypted on install; private release URLs never reach a client — such entries are served without `url` (`installable` marks them), `POST /plugin/marketplace/{name}/install` installs by name and resolves dependencies first, and the manage API withholds the stored URL (`url_hidden`). A dependency cannot be disabled or deleted while a dependent is enabled. Catalog entries carry `version` and `updated_at`; **a plugin's version is its release tag** (`build_info.release`) — the manifest `version` key is retired. A paid plugin the license already grants installs enabled. `plugin.marketplace.enabled: false` removes the shop entirely (endpoints answer `400 PluginMarketplaceDisabled`). → [Plugin Manager](../../for-administrators/plugin-manager/README.md), [/marketplace](../../for-developers/api/endpoints/plugin/marketplace.md), [secure plugin delivery](../../for-developers/concepts/white-papers/secure-plugin-delivery.md). [f0e99554d] [e596ca7d8] [674c63131] [487cad950] [2e14701dd]

#### The easydb plugins migrate to the marketplace

The images and release archives no longer carry the easydb disk plugins. On upgrade each **enabled** disk plugin with a successor becomes a url plugin on that successor's release, matched by manifest name; a disabled one, or one without successor, is removed. Eight successors have a different name, and the migration follows the rename into stored settings, `plugin.<name>.<right>` grants, export producers and transports, and — for barcode — the mask splitter type and the PDF Creator node. `commons-library` and `pdf-creator` are installed where a successor needs them; `server-pdf` is switched off where `pdf-creator` is enabled. Configuration carries over except across the one rename an admin has to redo by hand. Startup no longer waits on the plugin sources: zips are fetched in the background, update checks are spread over the day, a rate-limited source is backed off. → [Disk to URL plugin migration](../../plugins/disk-to-url-migration.md). [30f15a1c3]

#### License-gated plugins

A license can list, in a `plugins` capability map, which plugins an instance may enable. A named plugin the license does not grant is force-disabled at runtime (the stored `enabled` flag is kept, so it re-enables when granted) and refused over the API with `PluginNotLicensed` (403); unnamed plugins stay unrestricted. Which plugins are paid is the catalog's word, matched by name on every install path. → [License management](../../license-management.md). [d879cae2f] [297a219921] [1088324b2]

#### Plugin callbacks can write into the saving transaction

`db_pre_save`, `transition_db_pre_save` and collection-upload callbacks receive an `api_tx_url`. `/db` requests to it run inside the request's open write transaction, commit or roll back with the save, and read back within it; `plugin_user` works there too. A failed write on that URL fails the whole save. `await_index` is not available on it; behind NAT the host honours `callbackBackendOwnURL`. → [The callback contract](../../for-developers/plugin/callbacks/contract.md). [2011b1984]

#### 3D assets

`splat`, `spz`, `ksplat`, `ply`, `ply.zip`, `ply.gz`, `stl`, `obj`, `3ds`, `glb`, `gltf`, `nxs` and `nxz` get the file class `3d`. fylr renders the previews itself for gaussian splatting scenes (`splat`, `spz`, `ply`) and polygon meshes (`ply` with faces, `stl`, `obj`), picks a viewpoint automatically, and adds a compact `splat` interchange rendition for the 3D viewer; the other extensions are accepted and classified but not decoded. The camera is stored per asset via the `splat-view-select` produce parameter (`fylr convert --splat-view` accepts COLMAP/3DGS matrices). `GET /api/v1/settings` now lists the extensions a class accepts on upload, not only those it produces for. → [3D assets](../../for-developers/file-worker.md#3d-assets). [7d5129cf2]

#### Download dialog options are grantable per user and group

The `frontend_features` parameter **Download Options** grants the `filename`, `variants` and `custom` sections of the download dialog separately. Advisory to the frontend, nothing server-side is gated. The upgrade turns all three on for everyone holding the download right. → [Downloading](../../for-users/download-and-export/downloading.md#download-options). [52d48fd52]

#### 360° media are recognized

A spherical video or panoramic image carries `technical_metadata.projection_type` (for example `equirectangular`), read from the Spherical Video V1/V2 metadata and the XMP GPano tags. Produced versions keep the marker as long as the conversion keeps the full frame. → [Metadata extraction](../../for-developers/file-worker.md#6-metadata-extraction). [6ea606aef] [44120f79b]

#### Produce new versions from videos

`POST /eas/produce` accepts video originals: trim (`trim.start` / `trim.end`), mute, rotate in 90° steps, mirror, crop, scale to `height`, and a `color` object with temperature, tint, exposure, contrast, highlights, shadows, whites, blacks, saturation, vibrance and hue (neutral at `0`). Targets: `mp4`, `mov`, `m4v`. The response returns the new file `pending`; poll until `done` or `failed`. `webp` image sources are producible now. → [/eas/produce](../../for-developers/api/endpoints/eas/produce.md). [f4be96604]

#### Plugin manager shows a README tab

A plugin's docs are the `README.md` next to its `manifest.yml`; `manifest.has_readme` marks it in the manage listing and `GET /plugin/manage/{id}/readme` serves it. The `plugin.webfrontend.readme` manifest key is retired. → [/manage](../../for-developers/api/endpoints/plugin/manage.md#readme-zip-and-source-check). [419d82c60]

#### Plugins report an unreachable source

When a `url` plugin's source cannot be fetched, the plugin manager shows a warning with the reason (`url_unreachable`, `url_http_error`, `zip_invalid`) and since when. A plugin with a stored ZIP keeps running on it; one whose ZIP never arrived (`state: "not_installed"`) is force-disabled until the download succeeds. **Retry** (`POST /plugin/manage/{id}/check`) forces a source check; **install as ZIP** uploads the ZIP onto the same plugin, which becomes a `zip` plugin keeping name, configuration and state. A settings-only save no longer contacts the source. → [Plugin Manager](../../for-administrators/plugin-manager/README.md). [2e14701dd]

#### One bounded HTTP client for outbound requests

Plugin sources, webhooks, execserver callbacks, e-mail images, backups and exports share a client that bounds connect, TLS handshake and the wait for response headers; plugin probe and download are additionally bounded per operation. Timeouts, the HTTP/2 switch and per-URL overrides live under `fylr.debug.http`. → [fylr.example.yml](../../for-system-administrators/configuration/fylr.example.yml.md). [2e14701dd]

#### The topology page shows the whole installation

Every fylr server, every execserver, the load balancer when there is one, and the work between them — running, queued, finished, failed, throughput — updated over a websocket; JSON at `/inspect/system/topology/data`. An execserver registers each connected fylr and verifies at connect time that the announced callback URL comes back to that server, so a callback address pointing at a load balancer is reported on the page instead of failing inside a job. → [Fleet topology](../../for-system-administrators/inspect/system.md#fleet-topology). [ffe0f7b9c]

#### Unknown config keys are reported

Every config file is checked against the settings fylr knows: unknown and deprecated keys are logged at startup, listed on the `/inspect` config page with their file, and reported by `fylr config check <file>...`, which exits non-zero on an unknown key (`--strict`: on deprecated keys too). Mistyped `-s` parameters are reported as well; the environment is not checked. → [Checking the configuration](../../for-system-administrators/configuration/check.md). [4d90c3915]

#### Technical metadata says whether an image carries transparency

`technical_metadata.alpha` is present, and true, only for a file or rendition with an alpha channel. → [file](../../for-developers/system-data-types/file.md#technical-metadata). [2ea62b3006]

#### The datamodel model explorer

`/inspect/datamodel/<id>/model/` draws the object types of a datamodel and their links — one line per relationship, an `R` where it reads from either end, masters and what they own as one box — and shows a picked object type's columns, masks and fields beside it, with counts of the objects each holds. Filters for main search and unlinked types; available as JSON. → [Datamodel](../../for-system-administrators/inspect/datamodel.md). [e95288943]

#### Execserver commands can request temporary CPU allocations

Under an auto-balancing execserver a command may borrow CPUs from the shared pool through the loopback callback in `FYLR_EXEC_CONTROL_URL`. `fylr convert` does so around FFmpeg (up to `FYLR_CONVERT_VIDEO_MP4_THREADS` for an encode); extras never take the `fastReserve` slots, and a service's `maxSlots` bounds them together with its jobs. Every command carries `FYLR_EXEC_SUPERVISED=1` and its helpers stay in its process group, so the memory and stall watchdogs see them. Held extras appear as `extra_cpus` in the broker status, the topology and the `fylr_execserver_extra_cpus` gauge. → [Execution limits](../../for-developers/execserver.md#execution-limits). [bebc44b55]

### Improved

#### Colorspace of a custom version

A colorspace an ICC profile can express is converted through that profile and the file carries it: `rgb`/`srgb` → `sRGB_IEC61966-2-1_black_scaled`, `gray`/`grey` → `Generic Gray Profile`, `cmyk` → `ISOcoated_v2_eci`. One no profile expresses (`YCbCr`, `HSL`, …) converts as before. Colorspace and colour profile have to agree: a `cmyk` colorspace with an RGB profile is refused when the preset is saved. → [Custom Version Presets](../../for-administrators/readme/file-worker/custom-version-presets.md#color-space-and-color-profile). [920577b09]

#### Zoom of a transparent image

A transparent PNG keeps its transparency in the zoom; PNG tiles are transparent, JPEG tiles are laid on white. [920577b09]

#### Janitor: download and export retention

Download retention is configurable (default one day), and unscheduled exports can expire after a configurable period without a run; a rerun renews it. Historic file cleanup runs before export expiration and unused-file deletion, so previously downloaded files are reclaimed once nothing references them. → [Janitor](../../for-administrators/readme/services.md#settings-for-downloads-and-exports). [c4eba7428]

#### Janitor removes orphaned terms and custom data

`terms_delete` drops terms no record links to and removes them from the suggest index; `custom_data_delete` drops custom data entries no value refers to. Both take rows older than an hour, list their next batch on `/inspect/system/janitor/` and run on request; a manual run may carry `run_time` and treats it as now. Existing terms count as old, so the first sweeps clear the backlog in batches. → [Janitor](../../for-administrators/readme/services.md#orphaned-terms-and-custom-data). [55c269e16]

#### Object loading

Linked and historical reads reuse owner and group lookups within a request, cached reads fetch only the required standard entries, and standard construction and date parsing allocate less. [4a26c76c3] [5d8a11644]

#### The event stream takes its token from the websocket handshake

`GET /api/v1/event/stream` accepts the token as `fylr.auth.bearer.<token>` (base64url, no padding) in `Sec-WebSocket-Protocol`, next to the real subprotocol `fylr.event.v1` — the only way a browser can authenticate a websocket without the token in the URL. `access_token` keeps working. A refused handshake answers the JSON error `WebsocketUpgradeFailed`. → [/api/v1/event](../../for-developers/api/endpoints/api-event.md). [add7bde1f]

#### A plugin ZIP installs regardless of the file production settings

A plugin ZIP is exempt from the allowed-file-types and maximum-upload-size checks and no longer travels as an asset: `PUT /plugin/manage/upload` installs from the raw body, `POST /plugin/manage/{id}/upload` replaces an installed plugin's ZIP, `GET /plugin/manage/{id}/zip` returns it; `zip_file` is gone from the API. Uploading a ZIP onto a `url` plugin turns it into a `zip` plugin; a JSON save no longer changes the type. → [/manage](../../for-developers/api/endpoints/plugin/manage.md#readme-zip-and-source-check). [4c58c62fb, 6250def51]

#### Frontend staging hosts at *.web.fylr.io are trusted webOnly origins

The baked-in `loginAllowRedirects` default includes `https://*.web.fylr.io`; configs with their own list are unaffected. [024304e14]

#### Execserver scheduling and execution limits

fylr pushes a job onto a free execserver slot the moment one opens. The execserver runs one pool of slots for every service, classifies services light or heavy by measured runtime and keeps `fastReserve` slots for short jobs; the learned profile survives restarts. `slots` sizes the pool, 0 being `GOMAXPROCS`, the CPUs the Go runtime may use, which in a container is the CPU limit rather than the host's cores; a slot is a unit of admission, not a core, and a small container may set `slots` above its limit so short jobs overlap their transfers. `fastReserve: -1` reserves a quarter of the pool, `0` nothing, which is the setting for a fleet behind a load balancer. A service's `maxSlots` caps what it holds of the pool at once, jobs and temporary CPU allocations together: one soffice at a time, four slots for ffmpeg. Which execserver runs a service is what each one announces, so a dedicated execserver lists only its services and the `/job/<service>` address filter is gone. The `waitgroups` block and per-service `waitgroup` keys are reported as deprecated and ignored; `stallTimeoutSec` and `db.connMaxIdleTimeSec` are plain numbers with their defaults in `fylr.default.yml` and 0 meaning off; a `db:` block without the `+` suffix, which replaces the shipped pool values, is named at startup; the `?pretty=true` query of the old transport is gone from the shipped execserver addresses. Behind one load-balanced address fylr opens more pooled connections as jobs back up and re-probes the address whenever a backlog persists for more than a few seconds, so pods an autoscaler adds pick up work within seconds; `tokenResponseSendServerIP` is gone (`callbackBackendOwnURL` for NAT). On shutdown an execserver drains within `drainTimeoutSec` (default 20 s) and answers interrupted work with a retryable `503 ExecStopped`. Tuning keys: `slots`, `fastReserve`, `heavyThreshold`, `unknownShare`, `drainTimeoutSec`, per service `maxSlots`. Jobs run within a memory budget derived from host RAM or the container limit, with learned per-service footprints and per-job and shared ceilings; a command without progress for ten minutes is stopped (`stallTimeoutSec`, recipe `stallTimeout`, `"0"` disables); recipe `timeout` stays a wall-clock ceiling, long video encodes get 12 hours; receipts distinguish timeout, stall and memory aborts. → [Execserver](../../for-developers/execserver.md), [performance tuning](../../for-system-administrators/configuration/performance-tuning.md), [Scaling the execserver](../../for-system-administrators/installation/scaling-the-execserver.md), [slot broker white paper](../../for-developers/concepts/white-papers/execserver-slot-broker.md). [dc23ded29] [c7cc099cd] [58bf5cd15] [d9abc6263]

#### API responses no longer send the schema-version headers

`X-Easydb-Base-Schema-Version` and `X-Easydb-User-Schema-Version` are gone; use `X-Fylr-Cache-ID` for cache invalidation. [0fe459288]

#### CORS: credentialed requests limited to configured origins

An `Origin` is reflected with `Access-Control-Allow-Credentials: true` only when it is the `fylr.externalURL` origin, matches `fylr.services.webapp.loginAllowRedirects`, or is the origin of a registered OAuth2 client's redirect URI. Every other origin gets `Access-Control-Allow-Origin: *` and uses a bearer token. Responses carry `Vary: Origin`; `Access-Control-Allow-Private-Network` is no longer sent. → [HTTP and HTTPS](../../for-system-administrators/configuration/http-and-https.md#security-headers-and-cors). [0fe459288] [ad272dc93]

#### Security policy headers on every response

`Referrer-Policy: strict-origin-when-cross-origin`, `X-Content-Type-Options: nosniff`, and by default `X-Frame-Options: SAMEORIGIN` with `Content-Security-Policy: frame-ancestors 'self'`. A portal embedding fylr cross-origin lists its origin in `fylr.services.webapp.frameAncestors`; `X-Frame-Options` is then omitted. → [HTTP and HTTPS](../../for-system-administrators/configuration/http-and-https.md#security-headers-and-cors). [e9e8a7c6d] [00d56743c]

#### SQLite backend hardening

Callback tokens are minted before the saving transaction opens, lock contention surfaces as a retryable `423 DatabaseLockError`, background workers back off, SQLite-dialect errors map to their API errors, and background writes are bounded. Deleting a mapping a pool uses detaches it on SQLite too, `elastic.parallel` overrides win over the SQLite clamp, and `/inspect/collections` filters fold full Unicode. CI runs the critical API surface against SQLite. [2011b1984] [bdd48a4160]

#### Collection load errors are logged with their real cause

A database error behind an `ObjectNotFound` on a collection is logged with its full cause. [5f59ffe54]

#### Audio conversion: format, bitrate, cover art

`audioconverter:convert` offers `format` (`m4a` default, `mp3`, `aac`) and `bitrate` (128–320 kbit/s); cover art is carried into `m4a` and `mp3`; recipe texts are localized. Shown when the server reports `manifest.has_readme`, loaded on demand from `GET /plugin/manage/{id}/readme`; the legacy `webfrontend.readme` path is gone. → [Plugin manager shows a README tab](#plugin-manager-shows-a-readme-tab). (2d2291eae) (fea904abe)

#### Colour space and colour profile when producing a file variant

The produce dialog offers colour space and colour profile for image assets and sends them to `/eas/produce`. → [Colorspace of a custom version](#colorspace-of-a-custom-version). (4ee747fb0)

### Improved

#### Plugin manager: source warnings, retry and install as ZIP

A warning triangle in front of a plugin whose source cannot be fetched — orange while it still runs on its last download, red when its zip never arrived — with one warning text everywhere; **Retry** runs the source check in a dialog and reports healed or the fresh warning; **Install as ZIP** fetches the zip in the browser and uploads it onto the same plugin. → [Plugins report an unreachable source](#plugins-report-an-unreachable-source). (121c6878c)

### Fixed

#### File variants and the video editor were unreachable in builds with asserts on

`open_editor` no longer defaults to false. (a9c333e6f)

#### The context menu leaves the right button to the viewers that use it

The 3D viewer pans with the right button; the context menu stays away when the event was already handled. (22bb3023d)

#### A broken connector plugin no longer bricks the boot

With two connector plugins installed, a remote `<key>@<instance>` the other one merged into the schema fell back to the plain name instead of throwing inside the schema enrichment. (6f56efe08)

#### Share links

The `?login` flag is forwarded to the login and stripped afterwards, so a cross-server share link logs in once. (4d015cd72)
